# Tufts Mathematica

This repository contains an Open OnDemand Batch Connect app for running the
[Mathematica](https://www.wolfram.com/mathematica/) desktop GUI in an XFCE
desktop session on the Tufts HPC Slurm cluster (`pax`).

The app starts a VNC desktop on a compute node, loads the
`mathematica/<version>` module, and opens Mathematica. Users connect to it
from their browser through noVNC.

## Features

- Launches Mathematica `14.2.1` in a lightweight XFCE desktop, with desktop,
  device, removable-media, and trash icons hidden.
- Finds CPU partitions and their core, memory, and wall-time limits when the
  form loads, through a shared resource-discovery partial.
- Updates the core, memory, and hour limits when the partition changes.
- Optional "Request priority start" checkbox that submits with
  `--qos=interactive` and limits the resource fields to that QOS
  (4 hours, 16 cores, 64 GB). It is hidden on partitions where the
  interactive QOS does not apply.
- Optional email notification when the session starts.

## Repository Layout

- `manifest.yml`: Open OnDemand app metadata.
- `form.yml.erb`: Launch form. Partition, hours, cores, and memory fields are
  generated by `resource_discovery.erb` with `@partition_filter = :cpu`. It
  also holds the Mathematica version list.
- `form.js`: Browser logic for resource discovery and interactive-QOS limits
  (shared with the other Tufts apps).
- `submit.yml.erb`: Slurm submission template (time, CPUs, memory, partition,
  and QOS) using the `vnc` Batch Connect template. The QOS comes from the
  shared `partition_qos.rb` (for example `preempt` on the preempt partition,
  `normal-contrib` on lab partitions, `interactive` only where allowed).
- `template/before.sh.erb`: Exports the `module` function to the job.
- `template/script.sh.erb`: Starts XFCE, hides the desktop icons, loads
  `mathematica/<version>`, and runs `mathematica`.
- `icon.png`: App icon.

## Requirements

- Open OnDemand with Batch Connect and VNC support (TurboVNC and websockify
  on the compute nodes).
- Slurm scheduler.
- XFCE (`xfce4-session`, `xfdesktop`, `xfconf-query`) and `dbus-launch` on the
  compute nodes.
- `mathematica/<version>` and `openjdk` modules on the compute nodes, and a
  Mathematica license available to Tufts users.
- The shared site partials:
  - `/etc/ood/config/apps/dashboard/batch_connect/partials/resource_discovery.erb`
  - `/etc/ood/config/apps/dashboard/batch_connect/partials/partition_qos.rb`

## Usage

1. Choose a partition, wall time, cores, and memory.
2. Pick the Mathematica version.
3. Optionally check **Request priority start** for a short, small session.
4. Launch, wait for the session to start, then click
   **Launch Mathematica** to open the desktop in your browser.

## Site-Specific Configuration

These values are hardcoded for Tufts and need to be changed for another site:

- `form.yml.erb`: `cluster: "pax"`, the paths to the partials, and the
  version list.
- `submit.yml.erb`: `cluster: "pax"`, the email address domain
  (`@tufts.edu`), and the `partition_qos.rb` path.
- `template/script.sh.erb`: the `mathematica/<version>` and `openjdk` module
  names.

To add a Mathematica version, install the matching module and add it to the
`version` options in `form.yml.erb`.

## Troubleshooting

- **Desktop opens but Mathematica does not appear**: check `output.log` in
  the session directory to confirm that
  `module load mathematica/<version>` succeeded on the compute node.
- **Mathematica reports a license error**: the license server may be
  unreachable or all seats may be in use. Try again later or contact Tufts
  Research Technology.
- **Session never starts**: the requested resources may exceed what the
  partition or the interactive QOS allows. Lower them or uncheck
  **Request priority start**.
- **Blank or broken desktop**: confirm XFCE and `dbus-launch` are installed
  on the compute node.
